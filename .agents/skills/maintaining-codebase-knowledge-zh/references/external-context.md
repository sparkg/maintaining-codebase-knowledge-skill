# 使用外部系统和对话信息

## 使用边界

企业系统仍是其中记录的权威来源。本 Skill 可以读取用户为当前任务提供或明确授权的证据，但不会选择分配给谁的工作、批量复制外部系统、流转问题单、编辑 PRD、操作 CI 或写回状态。

只读取当前任务需要的内容。不要持久化凭据、客户数据、私密讨论、受限原文或仓库禁止保存的任何信息。

## 接收外部信息

只检查当前对话，以及当前对话可以访问的附件或导出文件。不要声称能够读取其他对话，也不要猜测无法打开的链接中有什么。

对于可能影响开发的信息，按 `knowledge-model.md` 中的证据规则，只记录以下内容：

```text
证据类型和可信程度
权威来源或任务标识
来源版本，以及提供或获取信息的时间
敏感程度
是否持久化以及保存位置
```

| 输入 | 处理方式 |
|---|---|
| 已批准的 PRD 或验收标准 | 作为目标行为的版本化证据记录，不能用来证明当前代码已经实现 |
| 用户对行为或故障的描述 | 在获得独立证据前，作为需求或运行情况的推测记录，可信程度标为 `hypothesis` |
| CI、测试、运行时或事故输出 | 只有能够确定运行记录或命令、代码版本、环境和时间时，才作为运行证据 |
| 任务分配、评论、流程状态或实时 CI 状态 | 只留在当前任务上下文或当前会话中 |
| 由企业或仓库管理的稳定规则 | 先确认来源权威性和仓库保存权限，再考虑写入长期项目知识 |
| 敏感或无法访问的内容 | 不要持久化；必要时标记为不可用，绝不猜测内容 |

长对话之后可能被压缩，因此允许保存的重要信息出现时应及时记录。只提炼开发需要的事实，不要复制原文。

## 判断哪些信息可以持久化

只有信息长期有效、与项目有关、仓库策略允许保存、来源充分且没有歧义时，才可以自动持久化。

- 长期有效的能力行为或约束写入对应的能力文档。
- 当前任务的验收条件、限制和待决定事项写入仓库允许的任务上下文或意图台账条目。
- 经常变化的流程状态和运行状态留在外部系统或当前会话中。
- 如果来源权威性、信息新鲜度、敏感程度或保存权限不明确，则不要持久化，并说明原因以及它对任务就绪状态的影响。

不要假设 `.agents/task-context/` 已被版本控制忽略或可以安全提交。写入前先检查仓库规则。保存的任务上下文只包含标识、来源信息、提炼后的需求、验收标准、限制、相关运行证据、冲突和未解决问题。

## 记录外部系统

只有外部来源确实影响开发时，才创建 `external-systems.md`。记录如何找到并管理该来源，包括用途、标识、负责团队、读取方式、权威记录判断规则、重新获取条件、敏感程度、写回权限和失败处理。不要复制完整记录，也不要列出密钥路径。
