# 在开发流程中使用项目知识

## 职责划分

本 Skill 提供项目知识。读取这些知识的开发流程仍负责设计、规划、隔离工作区、实现、测试、调试、评审、验证和交付。两者彼此独立：本 Skill 不会调用、配置或修改开发流程。

## 开发前应该读什么

开始设计、实现、调试或评审前：

1. 按仓库选定的 `AGENTS.md` 或 `CLAUDE.md` 中的指引，打开 `docs/project-knowledge/index.md`。
2. 如果索引中已有当前事项，读取对应的意图条目，以及它链接的能力或流程文档。如果索引中没有该事项，直接根据请求执行任务级 Deepen。不要尝试读取不存在的意图台账。
3. 按 `knowledge-model.md` 中的充分性标准，检查现有知识能否支持下一阶段。如果请求尚未记录、仍处于 `unrouted` 状态而没有指向负责该事项的文档，或内容不够深入，则执行 Deepen。只要知识索引已经存在，就不需要为了当前任务重新执行 Bootstrap。
4. 只有索引或意图条目明确指向当前任务上下文或已授权的企业信息时，才读取这些内容。
5. 根据就绪状态决定下一步：
   - `ready-for-design`：可以继续设计。
   - `ready-for-implementation`：可以继续实现；设计阶段需要的信息已经包含在内。
   - `needs-deepen`：执行 Deepen。
   - `needs-decision`：获得结果中指定的产品决策或授权决定。
   - `blocked`：解除结果中指出的阻塞项。

获得授权的设计流程可以处理明确委托给它的局部选择。在把任务标为可以实现之前，应将已经接受的选择记录到任务上下文中，或通过 Deepen 写入项目知识。

每类文档回答不同的问题：

- 能力文档：这项能力当前做什么、内部代码如何工作、哪些约束必须成立，以及如何测试；
- 流程文档：多项能力之间按照什么顺序工作，如何交接；
- 意图条目：任务要求改变什么、如何验收、还有哪些任务风险和缺失信息，以及能否继续；
- onboarding：当前任务适用哪些环境准备、验证和交付要求。

这些文档通过链接互相引用，不要在多个位置重复同一事实。

## 判断代码应该改在哪里

如果任务可能改变现有边界，先查看架构文档中“能力与实现单元的对应关系”和当前边界的证据，再查看相关能力文档中的放置依据。本 Skill 负责说明当前职责、现有扩展点、边界承受压力的迹象、已有决策和未知项。具体把改动放在哪里，由设计流程决定。

只比较仓库证据能够支持的方案：

- 通过现有扩展点增强当前能力；
- 修改多项能力之间的编排；
- 新增一项职责独立的能力或代码单元；
- 先重构已有证据表明承受压力的边界。

已经接受且影响较大的边界决策，应写入仓库的决策记录。实现稳定后，使用 Refresh 更新当前对应关系。

## 完成前的检查

实现稳定后，根据代码差异和任务证据执行 Refresh。只更新负责已变化事实的文档，删除已经被实现取代的说法，并返回分组的 Result Contract。

完成任务前，开发流程必须：

1. 验证任务链接的每项交付要求；
2. 如果任何必需信号仍然失败或缺失，则停止；
3. 重新运行实现检查，并执行该开发流程自己的完成步骤。

流转问题单、编辑 PRD、启动 CI、发表评论或改变企业流程状态，都需要在负责该操作的系统中另行获得授权。只要遵守这些边界，任何开发流程都可以使用本 Skill 生成的项目知识。
